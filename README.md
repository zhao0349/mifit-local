# MiFit Local · 小米运动健康本地工具

中文 Windows 数据导出工具，以及可独立使用的单文件离线健康仪表盘。

[在线演示（虚构数据）](https://zhao0349.github.io/mifit-local/) · [使用说明](使用说明.html) · [上游与贡献归属](THIRD_PARTY_NOTICES.md)

## 功能

- Windows 桌面界面：通过独立 Edge 窗口登录小米官网，按日期同步并更新当前账号的累计 JSON/CSV，也可按日期另存快照。
- 凭证保存到 Windows 凭据管理器；缓存和导出保存在项目目录内，按账号隔离。
- 离线仪表盘：日常活动、睡眠、心率、身体测量、运动概况、心率分时采样和睡眠阶段顺序。
- 身体详情支持体重、BMI、体脂率、肌肉量、体水分率、骨量、内脏脂肪等级、基础代谢和代谢年龄。
- 每类详情的“导出明细”可分页查看全部已知健康字段，保留同日多次测量、睡眠记录、心率/血氧/压力采样、异常心跳、运动报告、运动分时及 GPS 坐标，并导出筛选结果 CSV。
- 在浏览器中导入 JSON、筛选记录、下载汇总，以及保存包含数据的单个 HTML；离线副本保留逐条明细。
- 本机后端控制：桌面工具运行时，可在仪表盘中按日期读取缓存、官网登录、启动同步、查看分项进度并取消任务。

身体成分趋势取同一天最后一次测量，缺失字段不从较早记录补齐。明细按源文件顺序保留各次记录，字段名称及单位可展开查看；GPS 以坐标展示，无在线地图请求。来源未明确的步幅、恢复时间等单位保持“来源单位”，不自行换算。账号、设备、服务定位标识和未知扩展字段不进入仪表盘。

旧版日汇总不能恢复丢失的明细，需重新导入原始 JSON。为控制浏览器内存，逐条明细上限为 200 万条、4000 万单元格，单条文本上限 1024 字符；超限会拒绝导入并保留原档案，请用“按日期另存独立快照”缩小范围，不会静默截断。保存的 HTML 和明细 CSV 包含健康数据及可能的 GPS 坐标。
- 无前端框架、CDN、分析统计或数据上传接口。时间统一按北京时间显示。

## 直接使用网页

打开[在线演示](https://zhao0349.github.io/mifit-local/)，初始内容全部是固定种子生成的虚构记录。点击“导入数据”选择 Mi Fitness Data Bridge 导出的 JSON，文件在浏览器本地处理；点击“保存离线副本”即可离线使用。

访问在线页面会向 GitHub Pages 请求网页；健康文件不会由应用上传。下载后的 HTML 包含导入的健康记录，请勿提交到公开仓库或公开分享。更重视隔离时，先保存演示 HTML，再断网打开并导入个人文件。

## Windows 桌面安装

需要 Windows、Python 3.11 或更新版本（含 Tk）、Git、PowerShell 7 和 Microsoft Edge。建议使用已用于本地验证和 CI 的 Python 3.14；其他 Python 版本尚未完成同等验证。桌面凭证存储仅支持 Windows。

在 PowerShell 7 中执行：

```powershell
git clone https://github.com/zhao0349/mifit-local.git
Set-Location mifit-local
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\Start-MiFit.ps1
```

也可以双击 `启动小米数据导出.cmd`。先在手机“小米运动健康 Mi Fitness”中同步设备，再在桌面工具内登录和导出。本项目不适用于 Zepp Life。

运行依赖从固定的上游提交安装；`requirements-lock.txt` 是原 Windows/Python 3.14 环境的完整版本快照，其他 Python 版本建议使用 `requirements.txt`。

## 仪表盘连接本地后端

1. 启动（更新代码后重新打开）桌面工具，点击 **打开本机仪表盘**。桌面工具在运行期间监听 `127.0.0.1:17865`，关闭工具时停止服务并取消由网页启动的任务。
2. 也可以在新版离线/演示页面展开 **连接本地后端**，点击 **打开本机仪表盘**。它会打开新标签，当前手动导入的档案保留在原标签。没有运行后端时，仍可独立导入 JSON。
3. 点击 **读取本地缓存**，默认读取当前桌面账号的全部已缓存历史，不必先导出 JSON；需要缩小范围时将“读取”切换为“仅所选日期”。日期包含起止日，按北京时间归日；睡眠按醒来日期，与仪表盘保持一致。空缓存明确显示无记录，超出明细容量限制则保留当前档案并提示缩小日期范围。
4. 需要更新时点击 **小米官网登录** 或 **从小米同步**。打开网页和读取缓存不会访问小米；同步由你主动发起。界面显示成功、部分完成、失败和取消状态；完成后点击 **读取本地缓存** 更新图表。同步不会自动覆盖手动导入的档案。
5. 网页和桌面共用任务互斥；网页的 **取消任务** 只取消网页发起的任务，桌面发起的任务仍在桌面中停止。断线后当前档案保留，可以 **重新连接**；服务重启后需刷新网页以取得新的本机会话。

本机服务仅接收本机同源页面携带会话令牌的 API 请求，不提供跨站访问、任意文件读取或凭证输入接口。在线演示不会探测或读取你的本机数据。**保存离线副本** 会移除控制面板、控制脚本和会话令牌，恢复禁止联网的页面策略，仍包含你选择保存的健康记录。手机不能通过这个回环地址控制电脑，请使用离线副本查看。

操作划分参考固定版本上游 MCP 的 [`sync_data` / `get_sync_status` / `cancel_sync` 与缓存查询](https://github.com/shkyyy18/mi_fitness_data_bridge/blob/91ea4f15323c1c699e8c5ee8d044c0a820918851/src/mi_fitness_mcp/server.py)。上游使用 stdio 传输，浏览器不能直接连接；本项目通过本机 HTTP 适配层复用现有 `desktop_backend` 和上游同步服务，继续使用桌面账号的凭据及隔离缓存，不另起 MCP 账号配置。

若端口 17865 被占用，桌面会提示服务启动失败，原桌面导出仍然可用；不要把未知服务当成本项目后端。当前服务适用于本机桌面工具，不支持局域网共享或连接任意远程 MCP。

## 历史更新与账号隔离

- **默认追加更新**：SQLite 按上游记录主键插入或更新，未请求日期的旧记录保留，同一记录重复同步不会重复追加。账号 ID 和地区共同决定隔离目录；切换回账号后继续其原有历史。
- **累计导出**：桌面的“同步并导出”和“仅导出已有缓存”默认更新 `exports/<账号目录>/current/mi_fitness.json` 及 `current/csv/`，包含该账号全部缓存。每次从 SQLite 的一致快照生成完整结果，不拼接 CSV，也不因缩短本次同步日期而丢掉历史。日期是同步范围，不是默认累计导出的裁剪范围。
- **独立快照**：只有点击“按日期另存独立快照”才新建时间戳文件夹。旧版已生成的时间戳导出保留，不自动删除、猜测账号或导回数据库。
- **手动覆盖**：桌面或本机网页勾选“覆盖当前账号历史”后发起同步，必须再次确认账号和日期。仅当全部数据类型同步成功并完成清理后，才以本次范围的暂存数据库替换当前账号缓存。失败、部分成功、取消或账号变化均不会发布暂存结果。勾选在确认后自动复位，后续仍默认追加。
- 覆盖是有意移除当前账号活动数据库中范围外的旧历史，不是全盘擦除：已另存的文件不删除，其他账号不变；累计导出文件在下一次导出时重新生成。网页同步只更新 SQLite，桌面“同步并导出”还会更新累计文件。
- 文件发布先生成完整 JSON/CSV，再替换 `current`；发布失败恢复原结果。不同账号或地区不会共用累计文件。仪表盘手动导入仍独立使用，不把身份未知的旧文件自动并入任一账号数据库。

## 本地生成仪表盘

仅使用 Python 标准库即可生成演示，不需要安装桌面依赖：

```powershell
python dashboard_builder.py --demo --output dashboard/demo/健康仪表盘.html
```

已完成桌面同步后，可从当前账号的本机缓存生成私人仪表盘：

```powershell
.\.venv\Scripts\python.exe dashboard_builder.py
```

默认输出到 `dashboard/output/健康仪表盘.html`。个人缓存、导出和生成的网页均被 Git 忽略。不要使用 `git add -f` 将它们加入仓库。

## 开发与验证

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
node --version
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m ruff check .
```

浏览器测试使用 Microsoft Edge 和临时浏览器配置；JavaScript 数据处理测试需要 Node.js。默认跳过大型虚拟文件压力测试，可设置 `MIFIT_RUN_WORKER_STRESS=1` 启用。测试使用虚构记录，不连接真实账号。CI 在 Windows 上执行同一套测试；这不能代替真实设备、账号和实体手机验收。

## GitHub Pages

在仓库 Settings → Pages 中选择 **GitHub Actions**。推送到 `main` 后，工作流先运行测试，再用 `python scripts/build_pages.py` 构建仅含虚构数据的 `_site/`，最后部署该目录。构建器没有个人数据库输入参数，且不复制本地生成的健康网页。
